## א. מטרת הביקורת

לוודא שכל רשומה שמסווגת כ-**Web**, **Advertisement** או **Other** מגובה בראיה מתועדת הניתנת לאימות עצמאי — ולתקן סיווגים שגויים כדי שהדיווח ל-CMO/CEO ישקף מציאות ולא ארטיפקט טכני.

**מדד קבלה (Acceptance Criterion):**
לאחר הביקורת, ≥ 95% מהרשומות בשלושת הקטגוריות מחזיקות לפחות ראיה אחת מסוג מתועד (UTM / Cookie Session / הערת מכירות / Integration Log) שתואמת את תווית המקור שלהן. רשומות שנותרות ללא ראיה מסומנות "Unverified" ומועברות לטיפול.

---

## ב. הגדרות מחייבות לכל קטגוריה

| קטגוריה | הגדרה תפעולית | ראיה מקובלת | ראיה שאינה מקובלת |
|---|---|---|---|
| **Web** | ליד שנוצר ישירות דרך טופס / צ'אט / דף נחיתה באתר UPE, ללא מדיה בתשלום | Session cookie + HubSpot form submission log | "המתעניין כנראה ראה את האתר" ללא לוג |
| **Advertisement** | ליד שנוצר ישירות ממודעה ממומנת (Google Ads, Meta, LinkedIn Campaign) שמשויכת ל-UTM מתועד | UTM param בנתיב ה-URL (`utm_medium=cpc` / `paid-social`) + CRM integration log מהפלטפורמה | לחצו על מודעה בעבר ללא UTM על הסשן הרלוונטי |
| **Other** | כל ליד שלא ניתן לשייך לאף קטגוריה מוגדרת אחרת | הערת נציג מפורשת + אישור שאין Session cookie רלוונטי | רשומה שיובאה ב-Import ולא סווגה ידנית |

> **הערה HubSpot:** ה-Original Source property נרשם אוטומטית בכל פעם שמישהו נוחת באתר, אך חשוב להבין ש-Original Source עוקב אחר מקור התנועה (Marketing), ולא בהכרח אחרי השיטה הטכנית שבה נוצרה הרשומה.

## ג. שלבי הביקורת — פרוטוקול מלא

### שלב 1: ייצוא נתונים גולמיים

**מה לייצא (HubSpot / CRM):**

```
שדות חובה לכל רשומה:
- Contact ID
- Create Date
- Original Source
- Original Source Drill-Down 1
- Original Source Drill-Down 2
- Latest Source
- UTM Source (custom field אם קיים)
- UTM Medium
- UTM Campaign
- Associated Form Name
- Owner (נציג מכירות)
- Notes (last 3)
- Import Name (אם רלוונטי)
```

**פילטור:** ייצא רק רשומות שנוצרו בין [תאריך התחלה] ל-[תאריך סיום הביקורת].

---

### שלב 2: בדיקת Web — עץ החלטה

```
רשומה מסווגת כ-Web?
│
├── יש Form Submission Log בהיסטוריית הרשומה?
│   ├── כן → האם הטופס שייך לאתר UPE (לא לדף Meta/LinkedIn)?
│   │   ├── כן ✅ → ראיה תקינה. סמן: VERIFIED-WEB
│   │   └── לא ⚠️ → ייתכן Advertisement — העבר לשלב 3
│   └── לא → בדוק Session Cookie / HubSpot Activity Log
│       ├── יש Page View על דפי UPE.co.il / UPE.com?
│       │   ├── כן + אין UTM paid → ✅ VERIFIED-WEB
│       │   └── כן + UTM medium=cpc/paid → ⚠️ מסווג שגוי → העבר ל-Advertisement
│       └── אין שום פעילות אתר מתועדת → ❌ UNVERIFIED → פתח חקירה ידנית
```

**בעיות נפוצות ב-Web:**
- קישורי HubSpot Meeting מסווגים לעיתים קרובות כ-Direct Traffic אם לא מוגדרים כהלכה — בדוק שרשומות Direct שהגיעו דרך Meeting Link לא נכנסו ל-Web בטעות.
- רשומות שיובאו (Import) מוגדרות לעיתים כ-Offline Sources אך מופיעות תחת Web — השתמש ב-Original Source Drill-Down 1 כדי לזהות את שם ה-Import ולסווג מחדש.

---

### שלב 3: בדיקת Advertisement — עץ החלטה

```
רשומה מסווגת כ-Advertisement?
│
├── יש UTM params בנתיב ה-URL (Drill-Down 2)?
│   ├── כן → utm_medium = cpc / paid-social / paid-search / display?
│   │   ├── כן ✅ → VERIFIED-ADVERTISEMENT
│   │   └── לא (e.g. utm_medium=email) → ⚠️ מסווג שגוי → העבר לקטגוריה הנכונה
│   └── לא UTM → בדוק Integration Log (Google Ads / Meta / LinkedIn)
│       ├── קיים Lead Gen Form Submission מהפלטפורמה הממומנת?
│       │   └── כן ✅ → VERIFIED-ADVERTISEMENT (ראיה: Integration ID)
│       └── אין Integration Log → ❌ UNVERIFIED
│
└── ✅ = תיעוד את Campaign Name + Platform ב-Notes
```

> **הפניה:** Attribution מבוסס-נתונים (כגון ב-Google Ads וב-GA4) מחלק קרדיט על פני כל נתיב ההמרה — כדאי להשלים אותו עם UTM tracking ברמת ה-CRM לצורך קרוס-ולידציה.

**בעיית ה-"Last Click" ב-Advertisement:**
- Last-click attribution מעניקה יתר קרדיט ל-Direct ו-Branded Search, ו-First-click מעניקה יתר קרדיט לערוצי מודעות Awareness — שים לב שרשומה שהגיעה "ישירות" לאתר לאחר קליק על מודעה עלולה להיות מסווגת כ-Direct ולא כ-Advertisement.

---

### שלב 4: בדיקת Other — עץ החלטה

```
רשומה מסווגת כ-Other?
│
├── יש הערת נציג מפורשת המסבירה את המקור?
│   ├── כן → האם המקור שתואר מתאים לקטגוריה אחרת?
│   │   ├── כן (e.g. "ראיון בכנס" → Event, "המלצה" → Referral)
│   │   │   └── ⚠️ Re-label לקטגוריה הנכונה + תעד את השינוי
│   │   └── לא — אין קטגוריה מתאימה אחרת → ✅ VERIFIED-OTHER
│   └── אין הערה → בדוק Import History
│       ├── יש Import? → בדוק שם ה-Import ומקורו
│       │   ├── Import של כנס / אירוע → Re-label: Event
│       │   ├── Import של ספק לידים → Re-label: Advertisement / Purchased List
│       │   └── Import לא ידוע → ❌ UNVERIFIED → פנה לנציג שייבא
│       └── לא Import, לא הערה → ❌ UNVERIFIED → בדיקה ידנית חובה
```

> רשומות "Offline Sources" או "Direct" שהצטברו בגודל חריג הן סימן לתקלה בייחוס — אותו עיקרון חל על קטגוריית Other מנופחת.

> ביקורת חודשית של רשומות עם מקור "Unknown" או "Other" גנרי היא שלב מחויב המציאות לשיפור לוגיקת המיפוי.

## ה. כללי Re-labeling מחייבים

> ⚠️ **Re-labeling ≠ יצירת ליד חדש.** הספירה הכוללת נשארת זהה. מטרת השינוי היא דיוק הדיווח בלבד.

### מותר לשנות תווית מקור אם:
1. נמצאה ראיה מתועדת שסותרת את הסיווג הנוכחי (UTM, Integration Log, הערת נציג).
2. השינוי מתועד ב-Audit Log (מי שינה, מתי, על בסיס איזו ראיה).
3. ה-Original Source בהיסטוריית HubSpot נשמר (אל תדרוס אותו — צור Custom Property נפרדת: `UPE_Verified_Source`).

### אסור לשנות תווית מקור אם:
1. אין ראיה מתועדת — רק "לדעתי" או "כנראה".
2. הסיווג שנוי במחלוקת בין שני נציגים — יש להעלות לאחראי ולתעד.
3. מדובר בשינוי רטרואקטיבי לשיפור מצגת KPI ללא בסיס עובדתי.

## ח. המלצות מניעה (Post-Audit)

לאחר השלמת הביקורת, יש להטמיע את השינויים הבאים כדי שהבעיה לא תחזור:

1. **UTM Policy מחייבת:** השתמש ב-UTM tracking ברמת ה-CRM לקרוס-ולידציה — כל קמפיין ממומן חייב לכלול `utm_source`, `utm_medium`, ו-`utm_campaign` לפני אישור.

2. **Stamping Workflow ב-HubSpot:** מפה את ה-Original Source לשדה מותאם אישית (Master Source) באמצעות Workflow, כך שמקורות לא-דיגיטליים (כנסים, הפניות, outbound) יקבלו תיוג מדויק.

3. **ביקורת חודשית שוטפת:** עקוב אחר ביצועי כל מקור ליד בנפרד, והיה מוכן לשנות אסטרטגיה על בסיס תובנות אלה. קבע ביקורת חודשית קצרה (30 דקות) על רשומות Other.

4. **בדיקת שלמות שדות:** שיעור מילוי של פחות מ-80% בשדה Original Source שובר את יכולת הסגמנטציה — הגדר alert אוטומטי אם שיעור המילוי יורד.

5. **אימות Integration:** בדוק שה-CRM מוגדר נכון לקבל לידים מכל ה-Integrations ואמת שהרשומות מטופלות כהלכה.

6. **Custom Property נפרד:** צור שדה `UPE_Verified_Source` (לא לדרוס את Original Source של HubSpot) — Original Source רושם כיצד הקונטקט נכנס לראשונה ל-CRM וחשוב לשמור אותו ל-audit trail.

## י. מדד קבלה (Acceptance Criterion) — ניסוח מדיד

> ✅ **הביקורת הושלמה בהצלחה כאשר:**
> 1. 100% מהרשומות בקטגוריות Web, Advertisement, ו-Other עברו בדיקה מול עץ ההחלטה בסעיפים ב'-ד'.
> 2. ≥ 95% מהרשומות מסומנות VERIFIED עם ראיה מתועדת.
> 3. Audit Log מלא קיים ב-Google Sheet / Notion עם כל שינויי הסיווג.
> 4. Custom Property `UPE_Verified_Source` הוגדרה ב-CRM.
> 5. ספירת הלידים הכוללת זהה לפני ואחרי הביקורת (שינוי תוויות ≠ שינוי ספירה).
