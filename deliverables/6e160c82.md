## למה זה דחוף — 30 שניות לקורא

שגיאת `HTTP 400 / invalid_grant` פירושה שבקשת ה-OAuth נכשלת לפני שכל נתון מגיע ל-Salesforce. כל ליד ש-UPE מייצרת — מ-LinkedIn, מאתר האינטרנט, מכנסים — **נעלם ולא מתועד**. ללא נתוני לידים, כל החלטת שיווק היא ניחוש. זה ה-fix #1 לפני כל השקעה נוספת.

---

## שלב 0 — אבחון ראשוני (5 דקות)

פתח Salesforce → **Setup → View Setup Audit Trail** וחפש שינויים ב-Connected App בשבועות האחרונים. זהה מי ביצע שינוי ומתי.

---

## 🛣️ מסלול A — תיקון OAuth (מומלץ, פתרון קבוע)

### הסיבות הנפוצות ביותר ל-`invalid_grant` ב-2026

| # | סיבה | בדיקה מהירה |
|---|------|-------------|
| 1 | **Refresh Token פג תוקף / בוטל** | בדוק אם הסיסמה של ה-API User שונתה לאחרונה |
| 2 | **מדיניות Refresh Token "Immediately Expire"** | Setup → Connected Apps → OAuth Policies |
| 3 | **Permitted Users מוגבל** | Setup → Manage Connected Apps → Edit Policies |
| 4 | **IP Restriction חוסם את הקריאה** | בדוק אם ה-IP של השרת/כלי בטווח מאושר |
| 5 | **Security Token חסר** | רלוונטי אם ה-org מפעיל IP restrictions |
| 6 | **Spring '26 / Summer '26 — שינויי אבטחה חדשים** | בדוק PKCE + RTR |

---

### תיקון A1 — Re-authenticate (המהיר ביותר, ~10 דקות)

Salesforce מבטל את כל ה-access/refresh tokens של משתמש כאשר הוא משנה סיסמה. אם הסיסמה של ה-API User שונתה — **זה כנראה הסיבה**.

```
1. היכנס לסביבת Salesforce עם המשתמש שמשמש ל-API integration
2. Setup → My Personal Information → Reset My Security Token
3. עדכן את ה-Security Token החדש בכלי/פלטפורמה המתחבר ל-Salesforce
4. בצע re-authorization מלא (OAuth flow מחדש)
5. בדוק שהחיבור פועל עם קריאת test ל: GET /services/data/v60.0/
```

---

### תיקון A2 — בדיקת Permitted Users & OAuth Policies (~15 דקות)

השגיאה יכולה לנבוע מכך שמשתמש מסוים אינו מורשה לבצע self-authorize; ניתן לתקן זאת על-ידי מעבר ל-"All users may self-authorize" ב-Connected App Edit Policies.

```
Setup → Apps → Connected Apps → Manage Connected Apps
→ [שם ה-App שלך] → Edit Policies
→ Permitted Users: שנה ל-"All users may self-authorize"
→ IP Relaxation: "Relax IP restrictions"
→ Save
```

> ⚠️ **אבטחה:** לאחר שהחיבור חוזר לפעולה, חזור להגדרה מוגבלת יותר בהדרגה.

---

### תיקון A3 — Token Policy (אם ה-Token מוגדר לפוג מיידית)

Salesforce מאפשר לקבוע מדיניות מפורטת לתוקף ה-refresh token; ההגדרות נמצאות ב-External Client App → Policies tab → OAuth Policies.

```
Setup → Apps → Connected Apps → [שם ה-App] → Edit
→ OAuth Policies → Refresh Token Policy
→ שנה מ-"Immediately expire" ל-"Refresh token is valid until revoked"
→ Save
```

---

### תיקון A4 — Security Token (אם קיימות IP Restrictions)

אם ה-org מפעיל IP restrictions והמשתמש לא מתחבר מ-IP מאושר, יש לצרף את ה-Security Token לסיסמה; ניתן לאפס אותו דרך Personal → Reset My Security Token.

```
הסיסמה בחיבור צריכה להיות: [Password][SecurityToken]
לדוגמה: MyPassword123ABC456xyz
```

---

### תיקון A5 — Spring/Summer '26: PKCE + Refresh Token Rotation

Salesforce מחייב כעת דרישות OAuth מחמירות יותר כולל PKCE ו-Refresh Token Rotation; אפליקציות שמסתמכות על מימושי OAuth מיושנים עלולות לחוות שגיאות אימות.

שים לב: לאחר שה-Refresh Token עבר Rotation, ניסיון לממש את הטוקן הישן מתפרש כעדות לגניבת טוקן, ו-Salesforce מבטל את **כל** ה-refresh tokens הפעילים של אותו משתמש-אפליקציה.

```
Setup → Apps → [Connected App / External Client App]
→ Enable PKCE: ✅
→ Enable Refresh Token Rotation: ✅
→ ודא שהקוד שמנהל את ה-token מעדכן את ה-refresh token החדש לאחר כל קריאה
```

> 💡 **הערת 2026:** יצירת Connected Apps חדשים מוגבלת החל מ-Spring '26; ניתן להמשיך להשתמש ב-apps קיימים, אך Salesforce ממליצה לעבור ל-External Client Apps. אם יש צורך ב-app חדש — פנה ל-Salesforce Support.

### בדיקת חיבור — cURL מהיר לאחר תיקון

```bash
# Test 1: OAuth Token Request (Username-Password Flow)
curl -X POST https://login.salesforce.com/services/oauth2/token \
  -d "grant_type=password" \
  -d "client_id=YOUR_CONSUMER_KEY" \
  -d "client_secret=YOUR_CONSUMER_SECRET" \
  -d "username=YOUR_API_USERNAME" \
  -d "password=YOUR_PASSWORD_PLUS_SECURITY_TOKEN"

# Test 2: אם קיבלת access_token — בדוק שה-API עובד
curl -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  https://YOUR_INSTANCE.salesforce.com/services/data/v60.0/sobjects/Lead/

# תשובה תקינה: {"maxBatchSize":200,"recentItems":[...]}
# תשובה שגויה: {"message":"Session expired...","errorCode":"INVALID_SESSION_ID"}
```

> ⚠️ **אבטחה:** בעת פיתוח אינטגרציות OAuth, תמיד העבר מידע רגיש בגוף בקשת POST או ב-header; אל תשתמש ב-GET parameters — מידע רגיש כולל usernames, passwords, OAuth tokens ו-client secrets.

## 🛡️ מסלול B — Bridge זמני: הזנת LeadSource ידנית (עד שהאינטגרציה חוזרת)

**מטרה:** לא לאבד שיוך מקורות לידים שמגיעים בזמן שהאינטגרציה עדיין שבורה.

### B1 — הגדרת Picklist ערכים ל-UPE (פעם אחת, ~10 דקות)

LeadSource הוא שדה סטנדרטי ב-Salesforce שרושם מאיפה הגיע הלקוח הפוטנציאלי; הוא Picklist מבוסס Standard Value Set שמנהלי המערכת יכולים להתאים.

```
Setup → Object Manager → Lead → Fields & Relationships → Lead Source
→ New (הוסף ערכים רלוונטיים ל-UPE):
```

| ערך לפי טקסונומיה | ערך Salesforce API |
|-------------------|---------------------|
| LinkedIn Organic | `LinkedIn_Organic` |
| LinkedIn Paid | `LinkedIn_Paid` |
| אתר אינטרנט (Web Form) | `Web` |
| כנס / אירוע | `Conference` |
| הפניה (Referral) | `Referral` |
| רשימת דיוור / Email | `Email_Campaign` |
| שיחה יוצאת (Cold Outreach) | `Cold_Outreach` |
| גוגל / SEO | `Google_Organic` |
| גוגל Ads | `Google_Paid` |

> שמור על ה-Picklist הסטנדרטי לערוץ, והוסף שדה custom נפרד לפרטים: קמפיין, landing page, ומסע. עומס-יתר על שדה אחד מקשה על דיווח, לא מקל.

---

### B2 — שדות Custom נוספים (לאטריביוציה מלאה)

Pattern מומלץ: שמור קטגוריות רחבות ב-LeadSource ואחסן ערכי UTM בשדות custom כגון `UTM_Source__c`, `UTM_Medium__c`, ו-`UTM_Campaign__c`.

```
Setup → Object Manager → Lead → Fields & Relationships → New
→ צור שדות Text(255):
   • UTM_Source__c       (label: "UTM Source")
   • UTM_Medium__c       (label: "UTM Medium")
   • UTM_Campaign__c     (label: "UTM Campaign")
   • Lead_Channel_Notes__c  (label: "הערות ערוץ — זמני")
```

### B4 — Web-to-Lead Form כ-Bridge (אפשרות מהירה נוספת)

אם יש טופס Web-to-Lead קיים ב-Salesforce — **זה עדיין פועל גם כשה-OAuth שבור**, מכיוון שהוא משתמש ב-API שונה.

```
Setup → Feature Settings → Marketing → Web-to-Lead
→ וודא שהוא פעיל (Enable Web-to-Lead: ✅)
→ הוסף שדה LeadSource נסתר בטופס:
   <input type="hidden" name="lead_source" value="Website">
→ קישור ישיר לכתובת: https://webto.salesforce.com/servlet/servlet.WebToLead
```
